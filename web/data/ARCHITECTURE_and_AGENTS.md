## 一、两套运行架构

### A. 默认模型（glm-4.7-flash）—— 精简架构
官方硬约束：固定 1 并发、建议 25-30s 超时、高峰易 429/503 → 默认模型走最轻路径。

```
用户输入
→ 意图门(规则 isSimpleQuestion，不调LLM)   闲聊→主提示词单轮直接回答；否则放行
→ 检索：KB.load(kb_corpus) + KB.search + KB.hybridSearch(TF-IDF+bge向量)
        检索舰队【不派】多Agent；质量门控低分→改写CRAG；红线过滤
→ 组装 messages（含【默认免费模型·精简模式】指令）
→ agentLoop：主Agent 单并发(LLMLock≤1)+40s超时，一次到位，少工具调用
→ 质检：默认Flash【跳过】A/B 双Agent，直接 PASS
→ 输出
```
并发：全局 LLMLock 串行 ≤1（所有 callLLM 统一）；超时：默认模型 40s；多 Agent：意图门规则、检索舰队不派、质检 A/B 跳过。关键 message：`【默认免费模型·精简模式】…免五轮评测/少工具/一次到位`。

### B. 自填 API（任意 OpenAI 兼容模型）—— 完整架构
```
用户输入
→ 需求理解 Agent(INTENT_PROMPT，LLM)  判闲聊→直接回答；否则放行+注入明确需求
→ 检索：KB.load(corpus)+KB.search+KB.hybridSearch(bge向量+CRAG+红线)
        → 检索舰队 RetrieveFleet：总Agent + ≤3检索子Agent（子Agent只产素材/不答用户）→【检索素材包】
→ 联网 webSearch
→ 组装 messages：主提示词+能力清单+画像+注入skill+模式+素材包+联网+历史+@引用+明确需求
→ agentLoop：工具循环 → 最终回答（120s 超时）
→ 质检 Agent-A审计 → Agent-B评判（双向≤3轮：PASS/PARTIAL_FIX/FULL_REGEN）
→ 输出
```

### A/B 差异表
| 环节 | 默认模型(A) | 自填 API(B) |
|---|---|---|
| 意图门 | 规则 isSimpleQuestion | LLM INTENT_PROMPT |
| 检索舰队 | 不派 | 总Agent+≤3子Agent |
| 质检 | 跳过 A/B 直接 PASS | A审计→B评判 双向≤3轮 |
| 工具调度 | 精简少调 | 全量(自建/自检/修复) |

| 反思/沉淀 | 受并发锁约束 | 全量(点赞/点踩/自动) |
