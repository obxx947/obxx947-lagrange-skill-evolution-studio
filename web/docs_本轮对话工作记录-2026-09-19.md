## 二、修掉的 bug

### 1. ★ 超主力的「系统被毁 → 武器停火」完全失效（影响所有超主力）

- **根因**：`subSystems` 用的是**槽位名**（"A武器系统"、"M主槽载机"），而武器所属模块名是**变体名**（"'利剑'指挥系统"）。引擎判定停火靠**名字匹配** → 对不上 → 模块武器在系统被毁后**照样开火**
- **修复**：建 `subSystems` 时解析所选变体，名字与类型都取变体
- **实测**：大帝 5 个系统名全部对上；把全部系统标记被毁后 **60 秒伤害 = 0**

### 2. 维修次数用错判据

- 文档《战斗机制》按**系统类型**：主武器 2 次 / 舰载机库 2 次 / 指挥 3 次 / **动力战斗内不修 0 次**
- 原实现按模块的 `selfRepair` 标记 → 超主力的 `moduleGroup` 槽位**全都没这个标记 → 全部 0 次**，一毁就永久
- 修完后：太阳鲸 护航艇坞仓2 / 综合武器库2 / 舰载机维护系统2 / 攻城无人机系统2；大帝 附加能源系统0、其余2

### 3. ★「能加点却显示未解锁」

- **根因**：前置判定写成了「**所有**前置都要点开」，实际是「**任一**前置点开即解锁」
- **依据**：全库 **1051 个节点有 2 个前置**，且两个前置都在左侧同一列 —— 树形的「两条分支任走一条即通」
- 修完实测：只点开 2 个前置中的 1 个，节点立刻解锁

### 4. 我自己写坏的几处

- **正则转义被 shell 吃掉**：`\d` 变成 `d`，导致「武器分散打击」这类**规则写了却没匹配上**（这是"分散打击一直不生效"的真因）
- **模拟器漏了 AP_M 清单**：新字段在数据侧标好了，引擎侧的"按系统生效"清单忘了加 → 全部被丢弃
- **太阳鲸 C2 第二门武器名是「附属」**：资料里「附属：BM-12×180T防御导弹系统」的前缀被上一轮提取脚本当成了武器名 → 已更正

## 五、踩过的坑（避免重犯）

1. **shell 里写正则会被吃转义**（`\d` → `d`）——这类替换一律用 Edit / Python 写文件，不要用 `node -e` 拼字符串（同类事故本轮又犯了 3 次）
2. **heredoc 会吃掉反斜杠**（Windows 路径必挂）——测试脚本一律用 Write 工具生成
3. **`JSON.stringify(db, null, 2)` 会把紧凑单行库写成 2 万行**——必须 `JSON.stringify(db)` 保持单行
4. **`importAddPoint()` 结尾有 `alert()` 会阻塞页面**——测试里调完要等足够久
5. **载机条目必须是完整舰船对象**——只写 `{id,name,count,slot}` 轻引用会导致载机没有 modules → 零输出（我第一版测试就这么写错，误判成产品 bug）
6. **在页面里写 `battleLogs = []` 会新建同名全局**——读到的是空数组，引擎推的是它闭包里的那个
7. **对比面板 DPM 时要按武器主目标选字段**——攻城武器的名义值在 `dpm.siege`、防空武器可能在 `dpm.antiAir`，拿 `dpm.antiShip` 比会得出假的巨大偏差
8. **headless 视口太矮时配队页底部 fixed 统计栏会盖住下方舰船行**——测试需 `setViewport({height:1400})`
9. **`｜`(U+FF5C) 与 `│`(U+2502) 是两个字符**——分隔符解析必须都放进字符类
10. **`pureRef` 判定必须放在分组判断之前**——否则这类节点会掉进"引擎未实现"桶、丢掉"无译文"的标注
