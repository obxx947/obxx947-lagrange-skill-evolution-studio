### 0.4 三条铁律（都是踩过的坑）

1. **新增属性必须只改一处**：属性分组的唯一定义在 `_build_bpstats.js` 的 `GROUPS`，写进 `blueprint_stats.json` 的 `groups` 字段，`simulator.html`（`buildApGroups()`）和 `addpoint.html`（`buildGroups()`）都读它。
   ⚠️ 历史上分组写在三个文件里，漏改一处就**静默失效**（已踩 3 次）。别退回去硬编码。
2. **改含转义的 JS 源码，用编辑器/Edit 工具，不要走 `shell + python/node -e` 做字符串替换**。
   实测：`\d` 被吃成 `d` 导致正则永不匹配（"武器分散打击"那条就是因此没生效）；`\n`/`\s` 同理。
3. **`JSON.stringify(db, null, 2)` 会把单行 minify 的库写成 2 万行 / 558KB** —— 写回一律 `JSON.stringify(db)`。

## 2. 逐条机制实现清单

格式：**文档原文 → 当前代码行为 → 实现要点 → 改哪里**。
`数据` 列含义：`有` = 数据齐全；`部分` = 有但不全；`无` = 数据里没有，**要外部输入**。

### M01 · 系统伤害（打系统 vs 打结构）

- **数据**：`部分` —— 仅 14/412 门武器有 `subSystemTargets`
- **文档原文**：文档：「武器发射后，会先被对方闪避、拦截，剩下的伤害还要看对目标系统的效率高低」「如VA战机对动力系统效率高，70%-90%的伤害打在目标系统上，10%-30%打在舰船结构值上；打在系统上的伤害全额生效，打在装甲上的伤害会被抗性抵抗」
- **当前代码行为**：现在 `executeShot` 只扣目标 `hp`，完全没有"打系统"这条路径；`subSystems` 只有 destroyed 标记，没有血量。
- **实现要点**：① 给 `subSystems` 加 `hp/maxHp`（数据见 M02）；② `executeShot` 命中后按 `weapon.subSystemTargets` 决定这一发打系统还是打结构；③ 打系统不减免、打结构走抗性；④ 系统 hp 归零 → `destroyed=true`（现有逻辑已能处理后果）
- **改哪里**：`executeShot`(3729)、`subSystems` 构造(3144)

### M02 · 系统独立血量

- **数据**：`无`
- **文档原文**：文档：「系统拥有独立的血量，这个数字只有编辑」「例：绝育大帝主武器22000 / 动力20000；CV3000 动力28000 + 机库26500」
- **当前代码行为**：数据里**一个字段都没有**。`ship_database.json` 的模块没有系统血量。
- **实现要点**：需要在模块或系统上补一个 `sysHp` 字段，**只能从用户/游戏里拿**。
- **改哪里**：`subSystems` 构造(3144) —— 拿到数据后加 `hp/maxHp` 两个字段即可

### M03 · 系统可被破坏的次数（1 次 or 2 次）

## 3. 条件触发类（127 个节点 / 95 种）—— 最高优先级


### 3.1 问题：不是"没做"，是"做错了"

这批节点**约 100 个已经被归类成可汇总数值**（`addable: true`），意味着：

> **条件被丢掉，效果被当成「开场就永久生效」。**

实例（9 个节点，最多的一种）：

```
文档/游戏：自身结构比例降至{X}%时，舰船闪避率提升{Y}%，持续{Z}秒，一场战斗只触发一次
引擎实际：开局就永久 +Y% 闪避 —— 不看血量、不限期、无视"只触发一次"
```

方向没反，但**时机和作用条件完全不对**。这比"没实现"更糟，因为它在悄悄给错误结果。

### 3.2 三档实现方案

| 档 | 类型 | 能否做 | 工作量 |
|---|---|---|---|
| **一** | 「自身血量/结构比例低于 X% 时…」「战斗开始后 X 秒内…」 | ✅ 能做 | 约 200~300 行 |
| **二** | 「每运行 P 轮后，下一轮…」「每 P 秒…」 | ✅ 能做 | 中等（引擎已有 `atkBatch/batchesRemaining` 轮次概念，`burst` 已跑通） |
| **三** | 「携带【溶解】状态」「附加状态」「可叠加 N 层」 | ⚠️ 要新建模 | 大（引擎没有 buff/debuff 框架，见 M31） |

### 3.3 第一档设计建议（可直接动手）

在 `_build_bpstats.js` 给这类节点产出结构化字段，而不是现在的 `stat + perLevel`：

```js
// 节点记录里加：
rec.cond = {
  kind: 'hpBelow',        // hpBelow | battleStart | everySec | everyRound | onKillSys
  threshold: 50,          // 血量阈值（hpBelow 用）
  duration: 10,           // 持续秒数
  once: true,             // 一场只触发一次
  effect: { stat: 'evasion', values: [0,4,8,12,16,20] }   // 按等级取值
};
```

然后在 `simulator.html` 的 `applyAddPointShip` 里，把这些**从 `shipB` 的常驻累加里剔除**，
改成塞进 `s.condEffects[]`；`processBattleTick` 每 tick 遍历一次，条件满足才把效果加进对应字段（并记 `until` 到时撤销）。

⚠️ **关键**：先从当前 `addable` 的累加里**摘出来**再改，否则会算两遍。
⚠️ 摘出来后 `_counted` 会掉，`addpoint.html` 的"自动汇总 N 个节点"数字要同步调整。

## 4. 「归了类但引擎没读」的 55 个节点

这些属性管线归了类、写进了 `blueprint_stats.json`，但 `simulator.html` 里**没有任何地方读它**。
（审计方法：grep 属性名并排除 `applyAddPoint*` 段落。机库类用短名 `g.dmg` 消费，会有假阴性，但下面这几个是真的没用。）

| 属性 | 节点数 | 现状 |
|---|---|---|
| `weaponDuration`（攻击持续时间+） | **30** | 引擎 **0 处引用**，连赋值都没有 |
| `repairArmor`（一次性维修装甲 +N 点） | 10 | 只在 `simulator.html:2460` 赋值那行出现 |
| `positionFix`（站位调整） | 8 | 只在 `:2671` 重置那行出现 |
| `aaLockDown`（受防空锁定效率影响下降） | 4 | 只在 `:2453` 赋值那行出现 |
| `hangarAaResist`（载机抗防空锁定） | 3 | 只在 `:2468` 赋值那行出现 |
| `sysHp`（系统血量） | **0** | 数据里一个节点都没有 |

**结论：真正生效的是 4347，不是 4402。**

改法：`weaponDuration` 最容易 —— 引擎有 `w.atkDuration` 字段（`executeShot` 的 `atkDur` 计算里用了），
把 `sh.weaponDuration` 加成进去即可。`aaLockDown` / `hangarAaResist` 要先有 M13/M16 的"防空命中率"概念才能接。
