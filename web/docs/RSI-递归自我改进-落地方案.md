# RSI · 递归自我改进 落地方案（面向本项目）

> 2026-10-05 制定。**本文件只是方案，没有实现**（用户："这个先不动"）。
> 用户原话：「主智能体可以给 12 个子智能体注入提示词让他们去干活，然后根据结果的质量和速度打分；我来判断，然后 LLM 根据我的判断 1-100 打分，直到收敛。」

---

## 0. 先把话说清楚（诚实边界）

1. **不能训练模型权重**。API 调用的 LLM 权重不在我们手里，"用 6000 次调用变聪明"是错觉。
   本项目里能做、且有真价值的 RSI 是：**进化【提示词 + 技能 + 工具组合 + 工作流 + 验收判据】这类"外置的智能"**。
   这与"神经元实验室"是两条并行线：那边进化配队与网络（参数级），这边进化"怎么干活"（文本级）。
2. **有效的前提是"可验证奖励"**：每一条被进化的提示词，都必须有冻结的评测集与判据，否则分数会像自对弈的分数一样"自欺膨胀"。
   本项目已有的经验直接适用（都是踩过的坑）：
   - 目标（尺子）必须**群体共享、且与个体解耦** —— 让个体自带尺子 = 自评膨胀（方案二A 10-05 的教训，原话"可以把自己的目标调成我这样就算赢"）；
   - **跨代比较只看冻结标尺**（fscore 思路）—— 判据版本号写死进台账；
   - **判据必须穷举**（模拟器审计第 28 条：只取单点断言会得出反向结论）；
   - **一次只动一个变量**（第 38 轮"同时改靶子口径+引擎"导致无法归因）；
   - 改动**可回滚**（保存每代提示词全文 + 版本号，一键回退到任一历史代）。

## 1. 总体架构

```
                    ┌──────────────────────────── 主智能体（Orchestrator）───────────────────────────┐
                    │ ① 生成/变异 12 个提示词变体（同一角色，注入 12 个子智能体）                     │
                    │ ② 调度 12 个子智能体跑【冻结评测集】（固定 20 条任务，同题同判据）            │
                    │ ③ 收自动指标（格式/工具合法/事实核对/耗时/调用次数）                            │
                    │ ④ 把结果按"同题并排"呈现给人（用户只做一件事：点选更好的一条 + 可选一句话理由）│
                    │ ⑤ 调 LLM 打分器：把【用户判断 + 自动指标 + 原话理由】映射成 1-100 分            │
                    │ ⑥ 选择/繁殖/收敛判定 → 下一代（回到 ①）                                       │
                    └───────────────────────────────────────────────────────────────────────────────┘
```

**为什么是 12 个**：用户指定。工程上取 12 = N=8 精英位 + M=4 探索位（与方案二A 的"双轨选择"同构：既要当下最好，也要保住"行为上不一样"的怪胎）。

## 2. 角色先定一个（第一期只做一个）

- 第一期角色：**「检索舰队」子智能体**（本项目现成的真实角色：把用户问题→知识库检索→结构化配队要点）。
  理由：任务边界清晰、有对错、单次调用便宜、失败模式肉眼可查。
- 后续再扩：意图门 / 质检A / 质检B / 反思 / 配队编排。**一次只进化一个角色**（一次一个变量）。

## 3. 评测集（尺子）——冻结、可版本化

- 20 条冻结任务，来自本项目真实历史问题（含已知正解/已知反例）：
  - 8 条"应命中知识库某篇"（判据：命中指定文件+关键结论，可字符串/向量核对）；
  - 6 条"应拒绝编造"（判据：不出现数据库里没有的数值；出现即扣穿）；
  - 4 条"配队必须过 FleetCheck"（判据：JSON 合法 + 校验器 0 错误）；
  - 2 条"速度基准"（判据：同模型下 ≤ 基准调用次数 + 墙钟时间）。
- 评测集放 IndexedDB（`lagrange_rsi`），带 `benchVersion`；**改评测集必须升版本号，跨版本分数不可比**（= 冻结标尺纪律）。

## 4. 打分（1-100）——三层结构

| 层 | 占比 | 谁给 | 说明 |
|---|---|---|---|
| 硬门禁 | 0 或否决 | 程序 | 格式非法/工具不存在/编造数值 → 直接 0，不进后续 |
| 自动指标 | 0–40 | 程序 | 判据命中率(20) + 工具调用效率(10) + 耗时(10)，按 20 条任务平均 |
| LLM 裁判 | 0–60 | LLM | 输入＝【同题两条输出并排 + 自动指标 + 用户点选 + 用户原话理由】；输出＝分项分 + 一句话证据。**LLM 不许改写用户的选择**，只做"把选择翻译成分数" |

- **用户判断的落法**（不让用户填表、不增加负担）：每代评测后，页面把"第 k 名的输出 vs 第 1 名的输出"并排展示 3 组，用户只点 `A 更好 / B 更好 / 一样`，可附一句话。
  用户的选择 → 一份"人类偏好"数据；LLM 裁判据此给分并说明理由。
- **防分数膨胀**：同一代所有变体用**同一条用户判断池**与**同一版判据**；LLM 裁判的温度固定 0；裁判输出与自动指标一起入台账，异常（分差>20 且无证据）标红人工确认。

## 5. 选择与繁殖（沿用方案二A 的成熟结构）

- 双轨选择：按总分取前 8（精英）+ 按"行为距离"（8 维行为向量：命中模式/拒绝模式/工具序列/长度/耗时…）取前 4（探索）；
- 繁殖：精英原样留 1 个 + 锦标赛抽父代 → **LLM 变异器**改写提示词（变异算子：加约束 / 删冗余 / 调顺序 / 换措辞 / 加示例，一次只上一类）；
- **变异红线**：不许改工具接口与字段名（那是程序契约，改了会整体崩）；只允许改"角色描述 / 工作流程 / 判据措辞 / 示例"。
- 每代产物：`{gen, 12 个提示词全文, 每变体分数, 用户选择, 裁判理由, 自动指标}` → 台账 jsonl（IDB + 可导出 JSON，正好配合"导出 JSON 塞上下文"）。

## 6. 收敛判定与停止

- 冻结标尺：`bestScore(冻结判据下)`；连续 **8 代** 提升 < 2 分，且 12 变体分数方差 < 5 → **已收敛**，自动暂停并给出"最优提示词"；
- 硬上限 24 代；任一硬门禁失败率上升 10% → 熔断回滚到上一代（防崩坏）；
- 停因与神经元实验室一致：**暂停 / 收敛 / 熔断 / 用户手动停**，全部先落台账。

## 7. 落地组件清单（本项目已有 vs 要新建）

| 能力 | 现状 | 要做什么 |
|---|---|---|
| Agent 循环（可注入提示） | ✅ `js/agent.js`（systemPrompt 从 `data/system_prompt.md` 加载） | 子智能体角色提示改成"可替换的变体对象" |
| Skill / 自定义工具 | ✅ `js/skills.js`（含导出 JSON，本轮新增） | 进化产物直接落成 Skill |
| 多模型/并发 | ✅ 设置页多模型；neuon 页有 Worker 池 | 子智能体用一个 Worker 池并发跑 12 变体（限并发=用户选） |
| 持久化 | ✅ IndexedDB 基建（`js/neuron/neuron_store.js`） | 加 `lagrange_rsi` 库（bench / generations / preference） |
| 评测集 | ❌ | 从历史对话与 fix_log 提炼 20 条（含正解/反例） |
| LLM 变异器 + 裁判 | ❌ | 两个系统提示词（变异器/裁判），接现有 LLM 调用 |
| 人评审 UI | ❌ | 新页 `rsi.html`：并排对比 + 三按钮点选 + 台账 + 收敛看板（样式抄 neuron 页） |

## 8. 第一期最小落地（建议排期：先做通再谈扩张）

1. 造评测集（20 条，半天）；
2. `rsi.html` 骨架 + 12 变体跑题 + 自动指标（1 天）；
3. 人评审点选 + LLM 裁判（0.5 天）；
4. 选择/繁殖/台账/收敛（0.5 天）→ 跑 8~12 代看曲线；
5. **验收**：最优代在冻结评测集上比第 1 代 ≥ +10 分，且失败样例集不退化（两把尺子都对才认）。

## 9. 与其它两条线的关系

- **神经元实验室**：进化"配队与打法"；RSI：进化"干活的提示词"。两条线的产物在同一页（配队页/对话）会师；
- **观察包解读**：方案二A 每 20 代产出的"观察包"正需要一个靠谱的解读提示词 —— 第一期 RSI 可以直接把"解读观察包"当第二个评测场景。
- 通用纪律（写进每一代台账头部）：**分数只是当时那把尺子量的；要回答"真的变强了吗"，只能看冻结评测集。**

---

### 附：为什么不去做"真·递归自我改进"（省得以后再问）

- 让 AI 改自己代码 → 需要"改完还能自动验证全对"的强判据；本项目可自动验证的只有部分（引擎回归/配队校验/知识库命中），代码级自改的爆炸半径远大于"提示词级"；
- 权重级 RSI 需要本地可训练模型 + 可验证奖励 + 大量算力，本设备（2GB 内存）不具备；
- **先把"提示词级 RSI"跑出真实增益**，再谈更大胆的层 —— 这也是用户"从混沌中长出来"思路的正确量级：先让它在能自证的小圈里进化。
