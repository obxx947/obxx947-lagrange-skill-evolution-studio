# 战斗模拟器 · 全部机制与计算公式（从代码逐行整理）

> 来源：`simulator.html` 的战斗引擎部分（`prepareBattle` / `processBattleTick` / `processShipWeapons` / `findTarget` / `executeShot` / `processRepairs` / `generateBattleReport`）。
> 本文只描述**代码实际在算的东西**。凡是"代码里写了但数据里没有输入"的，都在最后一节如实标注为**空转机制**。

---

## 一、时间与循环

| 项 | 代码 | 说明 |
|---|---|---|
| 每帧步长 | `dt = 0.1 × battleSpeed` | 逻辑步长固定 **0.1 秒**，速度倍率只是把一步跨多大 |
| 帧间隔 | `setTimeout(loop, 100 / battleSpeed)` | 1x=100ms、10x=10ms |
| 时间戳 | `bs.time += dt` | 战报里的"战斗时长" |

**推论：舰船 `speed`（巡航/曲速）完全不参与战斗**，只用于图鉴显示。没有先后手、没有接敌距离。

每帧做 4 件事：①所有存活舰开火 ②维修 ③子系统维修计时 ④判胜负。

## 二、编队与部署

1. 四个舰队面板各自收人：
   - `我方护航 → ally(我方)`、`我方被护航 → ally`、`敌方护航 → enemy`、`敌方被护航 → enemy`
   - 主舰队 + 增援 **都算**（增援不占人口，但**照样参战**）
2. 每条舰队条目按 `count` 复制出 N 个**实例**：`for(i<count) dest.push(createShipInstance(...))`
3. 实例是**浅拷贝**（`{...shipEntry}`），所以 `aircraft`、`modules` 等对象是**共享引用**
4. 载机部署（`deployAircraft`）：
   - 按**舰队条目**分组（`uid`），把该条目上的载机**按数量平均分摊**到它的 N 个单位上（余数给前面的）
   - **部署总数 = 配队页上填的数量**（大矛×6 配 10+8 → 战斗里就是 18 架）
   - 载机实例标记 `position='aircraft'`、`carrierId/carrierName`，并继承母舰的护航/被护航标记
5. 实例出场状态：`alive=true`、`hp = maxHp = hp × (1 + hpBonus/100)`

## 三、站位与目标选择（`findTarget`）

站位只有 `前排/中排/后排`（本轮已按你的《舰船排位》全量更正）；舰载机是 `aircraft`，不参与排。

选目标按**优先级顺序**（从高到低）：

1. **【优先打击超主力】**（仅当该船勾选）：只在超主力（战列/航母/战巡/支援）里挑
2. **【直射武器】** `weaponType==='direct'`：必须先打**敌人最靠前的那一排**
   - `getDirectFireTargets()` 从「前排→中排→后排」找**第一个有活人的排**，只能打这一排
   - 也就是：**前排没清完，直射武器碰不到中后排**
3. 在候选里按武器自带的 `targets` **攻击序列**逐条匹配（类型匹配见下），第一条匹配到就用
4. 都没匹配上 → 全体活人里随机

**候选收缩（防止全员集火同一艘）**：`splitCount = max(1, round(候选数 / 2.5))`，再在 `min(候选数, splitCount)` 里随机取一个。
> 即候选越少越集中；候选很多时只在前 1/2.5 里随机 —— 这是"分排/分流"的近似实现。

**类型匹配 `matchesType(ship, typeStr)`**：依次比对 ①英文 type ②中文舰种名 ③舰名包含该词 ④反向包含
⑤特例：`超主力舰`=superCapital、`大型舰船`=size large、`小型舰船`=size small 且非超主力、`舰载机`=size aircraft。

## 四、武器开火周期（`processShipWeapons`）

一门武器的循环是 **首射 → 冷却 → 锁定 → 攻击批次 → 冷却…**

| 阶段 | 代码 |
|---|---|
| **首射** | `firstShot=true` → 冷却/锁定直接清零，第一轮立刻打 |
| **冷却** | `cooldownRemaining -= dt`；**冷却与锁定同时进行**（锁定在读条时冷却也在走） |
| **锁定** | `lockRemaining = lockTime × (1 - 强化锁定减免/100)`；锁定没走完不开火 |
| **攻击批次** | 弹药 `ammo × attacks`：如 `3×2` = **2 个批次、每批 3 发**，在 `atkDuration` 秒内打完；批间隔 = `atkDuration / 总批数`；每批实发 `ceil(剩余发数/剩余批数)` |
| **atkDuration=0** | 一次把全部发数瞬发 |
| **打完** | `cooldownRemaining = cooldown × (1 - 强化冷却减免/100)` |
| **目标中途死亡** | **剩余发数/批数会带到新目标**（不重置） |
| **子系统被毁** | 该模块的所有武器**停火**（`modSys.destroyed → return`） |

## 五、命中判定（`executeShot` 第一段）

```
基础命中区间 = 该武器 targets 里匹配到目标类型的那一条的 [hitMin, hitMax]
命中率 = (hitMin + rand × (hitMax-hitMin)) / 100
命中率 ×= (1 + (武器.lockEfficiency − 目标.evasion) / 100)
命中率 = clamp(命中率, 0.01, 0.99)
若 轰炸模式 且 (攻击方或目标是舰载机):
    命中率 += (轰炸距离 − 15) × 0.02       # 每远 1 吉米 +2%
若 rand > 命中率 → 未命中（5% 概率记日志）
```
> 注意：**没有距离/速度影响**（除轰炸模式的距离滑块）；命中率完全由数据里的 `hitMin/hitMax` 决定。

## 六、拦截判定

**拦截率的来源（2026-09-18 新增）**：拦截值写在**模块**上，开战实例化时由 `applyIntercept()` 合成到舰船级：
```
舰船级拦截率 = 1 - (1-舰船基础值) × Π(1-各所装模块拦截率)
舰船级拦截类型 = 覆盖范围最宽的那个（global > sameRow > self）
```
`createShipInstance()` 与 `switchModuleVariant()` 都会调它 → **换模块会立刻改变拦截率**。

**判定**（`executeShot`，本段未改动）：
```
noIntercept = (1 − 目标.interceptRate/100)
              × Π( 1 − r/100 )   对每个存活敌舰 r=interceptRate：
                    interceptType==='global'   → 一律累乘
                    interceptType==='sameRow'  → 仅同排时累乘
                    interceptType==='self'     → 不进入这个循环（只由上面那一项代表"自身拦截"）
拦截概率 = 1 − noIntercept
若 rand < 拦截概率 → 攻击被拦下（10% 概率记日志）
```
（`cannotBeIntercepted` 为真的武器、以及 `weaponType==='direct'` 的直射武器跳过这段。）

## 七、伤害计算（核心）

```js
tuningCoeff = 1.3                                  // 基础调校系数，固定 +30%

dmg = 武器.singleDmg × (1 + 强化单发加成/100)

── 能量伤害 (dmgType==='energy') ──
若 (目标.energyArmor + 能量抗性加成) ≥ 100  → 伤害 0，直接跳过
dmg = dmg × (1 − (energyArmor + 能量抗性加成)/100) × 1.3

── 物理伤害 (其它) ──
破防后 = dmg − (目标.physicalArmor + 物理抵抗)      // 护甲是"减法"
若 破防后 > 0 → dmg = 破防后 × 1.3
否则          → dmg = dmg × 0.1 × 1.3               // 不破防：10% 保底伤害

── 暴击 ──
暴击率 = (武器有 crit 标记 ? 0.15 : 0) + 强化暴击率/100
暴击伤害 = 1.5 + 强化暴击伤害/100
rand < 暴击率 → dmg ×= 暴击伤害（10% 概率记日志）

── 乘区 ──
dmg ×= (1 + 攻击方.dmgBonus/100)                     // 舰船级伤害加成
若 受伤方旗舰是「普鲁图斯之盾(大盾)」且其指挥系统未毁 → dmg ×= 0.7   // 减伤 30%
dmg = max(0, round(dmg))

── 护航保护 ──
若 目标是被护航舰 且 本方护航舰还有存活 → dmg = 0          // 被护航舰在护航存活时"免疫"
```

**五条要点**：
1. **护甲是减法**（物理）/ **乘法**（能量），两者规则不同；
2. **不破防只吃 10% 伤害**，所以小口径打大船基本无效；
3. **调校系数 1.3 是全局乘数**；
4. **大盾旗舰全场减伤 30%**（只要它在且指挥系统完好）；
5. **被护航舰在护航存活时打不动** —— 这是"护航战斗"的核心规则，也是为什么必须先把护航清掉。

## 八、系统破坏（System Damage）

```
① 定向破坏：武器有 subSystemTargets 时
   效率 high=60% / medium=40% / low=20% 概率命中指定系统
   成功 → 该系统 destroyed、造成 武器.singleDmg × 1.5 × 1.3 的系统伤害
         且目标额外扣 5% 最大结构值
② 随机破坏：任何一次命中都有 10% 概率随机毁掉一个未毁、非引擎的系统，同样扣 5% 最大结构值
```
被毁的模块**所有武器停火**（见第四节），并可被维修。

**子系统维修**：摧毁后 **25 秒**自动修复一次；
可修复次数 `maxRepairs = 指挥系统 3 次 / 声明 selfRepair 的 2 次 / 其它 0 次`（0 次=永久毁坏）。

---

## 九、维修（`processRepairs`）

```
每秒维修量 = (武器.dpm.repair / 60) × (1 + min(目标物理护甲 × 0.25, 150) / 100)
```
- 「一点物理护甲 = 0.25% 受维修加成，上限 +150%」
- 目标按武器 `targets` 的**维修优先级**挑，同优先级里**选血量百分比最低的**
- 找不到符合条件的目标 → 回落为自己/最近友军（自修）
- 只有带 `dpm.repair` 的"武器"才维修（维修模块被当作武器建模）

## 十、强化（⚡）如何进入计算

| 强化项 | 作用点 | 上限 |
|---|---|---|
| 单发伤害 +% | `dmg = singleDmg × (1+加成)` | 100% |
| 锁定时间 −% | `lockRemaining = lockTime × (1−减免)` | 50% |
| 冷却时间 −% | `cooldownRemaining = cooldown × (1−减免)` | 50% |
| 暴击率 +% | 叠加到暴击率 | 50% |
| 暴击伤害 +% | 叠加到 1.5 倍 | 100% |
| 结构值 +% | `maxHp = hp × (1+加成)` | 100% |
| 能量抗性(0-100) | 能量伤害的减伤百分比 | 100 |
| 物理抵抗(固定值) | 加到物理护甲（减法里） | — |

强化按 `槽位_变体/武器序号` 存（`strengthen['M1'][0]`），**只有该武器读它**；改完立即影响下一帧。

## 十一、胜负与战报

- 一方 `存活数 == 0` → 结束，记"我方/敌方胜利"
- 战报统计：每方"总伤害"= 对方 `Σ(maxHp − 当前hp)`、存活数、战斗时长；逐舰给出存活%/损失HP

## 十二、模块切换的实际作用（你问的）

代码里切换是**完整的**：`switchModuleVariant()` 会移除该槽旧武器的 `weaponStates`、按新变体重建、并刷新子系统名；`createShipInstance()` 开战时也按 `selectedModules` 解析（未选则取第一个变体）。

**但当前数据下，切换只影响「载机位」，不影响武器** —— 原因见下一节。

## 十三、⚠️ 目前"空转"的机制（代码有、数据缺）

我逐字段核对了全库（196 艘 / 285 门武器）：

| 机制 | 代码读取的字段 | 数据现状 | 后果 |
|---|---|---|---|
| **拦截** | `舰船.interceptRate` / `interceptType`（由 `applyIntercept()` 从**模块**合成） | ✅ **2026-09-18 起 5 艘有**：雷火之星B2 27%、光锥级-区域防空 23%、大盾B3 12.8%、太阳鲸C3 5%、CV3000 A2 12% | 拦截**已真的生效**；其余 191 艘资料无数值，仍为 0 |
| **闪避** | `目标.evasion` | **0/196 有** | 命中率不会因此变化 |
| **锁定效率** | `武器.lockEfficiency` | 仅 **63/285** 门有 | 多数武器这一段是 0 |
| **暴击** | `武器.crit` | 仅 **14/285** 门有 | 暴击极少触发 |
| **定向系统破坏** | `武器.subSystemTargets` | 仅 **9/285** 门有 | 主要靠"10% 随机破坏" |
| **攻击方伤害加成** | `舰船.dmgBonus` | **0/196 有** | 该乘区恒为 1 |
| **模块武器** | `变体.weapons` | **0/233 个变体有** | **超主力模块切换不改变火力** |
| **速度** | `舰船.speed` | 有数据但**代码不读** | 无先后手/无接敌距离 |
| **评级** | `ratings` | 有数据但**仅图鉴显示** | 不参与计算 |

**所以现在真正决定胜负的是**：`singleDmg` × `ammo×attacks` / `cooldown`（火力密度）、`hitMin/hitMax`（命中）、`physicalArmor`（物理减伤）、`energyArmor`（能量减伤）、`hp`、`targets` 类型序列，加上：**直射先清前排**、**大盾旗舰减伤 30%**、**护航存活则被护航舰免疫**、**载机数量**。

## 十四、与真实游戏的关系（如实说明）

这套模拟器是**按游戏公开机制文档 + 数据表复刻的近似模型**，不是游戏的官方计算式。已经对齐的部分：护甲减伤/不破防保底、调校系数、直射分排、护航免疫、旗舰技能、子系统破坏与维修、舰载机搭载。

**尚未对齐或缺失**：命中率与闪避的真实分布、拦截的真实判定、速度/距离对交战的影响、模块对火力的具体加成（数据缺）、以及所有未在数据中体现的隐藏机制。

如果你能提供**模块武器数据**（每个变体的武器/DPM），模块切换就能立刻在战斗里生效；提供**拦截率/闪避**字段，拦截与闪避机制也会立刻活过来——代码侧都已经就绪，只等数据。
