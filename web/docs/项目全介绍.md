> 文档版本：2026-09-20
> 用途：一份能让任何人（包括新接手的对话）完整看懂这个项目是什么、做到哪一步、还差什么的说明。

## 一、这是个什么东西

一个**专门服务《无尽的拉格朗日》玩家的 AI 战术顾问**，纯前端静态站点（部署在 GitHub Pages），另有一个 FastAPI 后端做 API 代理与联网搜索。

它解决的问题是：**配队这件事靠人反复试错太慢**。所以它把三件事串成一条链：

```
查资料（知识库 + AI）
   ↓
配舰队（战舰配队页，同时充当"数据校验器"）
   ↓
验证强弱（战斗模拟器，用同一份数据算）
```

关键在于：**这三块读的是同一份舰船数据**。配队页算出来的人口/服役/载机位，就是模拟器开战时用的那一套；不会出现"配队页显示 420 人口、模拟器算出 500"这种对不上的情况。

### 现在能做什么（一句话清单）

| 能力 | 一句话 |
|---|---|
| **问 AI** | 多 Agent 流水线：门控分类 → 4 路并行检索 → 工具调用循环 → 双质检 → 打分放行 |
| **配舰队** | 主/增援、超主力模块多方案、载机按载机位分配、站位、旗舰，实时统计；**违规直接报错** |
| **加点** | 官方 177 艘加点树全量入库；左系统右网格；**配好开战自动生效**，不用导入 |
| **打一场** | 纯前端战斗引擎，四舰队编队、逐武器强化、模块切换，跑完出伤亡报告 |
| **查自己有几艘** | 用户舰船库：录入你实际拥有的船和模块，AI 可据此给方案（默认关，你开了才读） |
| **配队库** | 把现成配队存起来当 AI 的骨架，AI 配队优先查它，而不是从零编 |

## 四、AI 对话是怎么跑的

### 4.1 多 Agent 流水线

```
用户提问
  ↓
① 意图门（intent gate）      判断属于 配队/舰船数据/机制/闲聊，抽出人口预算、增援数、场景
  ↓
② 4 路子 Agent 并行检索      舰队配置 / 舰船数据 / 战斗机制 / 讲解范例
  ↓
③ 检索舰队（lead + ≤3 子代理）  对复杂问题再拆一层，主检索兜底
  ↓
④ agentLoop（最多 40 轮）    带 11 个工具自主调用
  ↓
⑤ 双质检                    QC-A（六步 found_issues）+ QC-B（三维度打分，≥75 PASS）
  ↓
⑥ supervisor / evolution     不合格打回重写；合格后沉淀经验
```

### 4.2 十一个工具（AI 按需调用）

| 工具 | 用途 |
|---|---|
| `search_knowledge_base` | 检索引擎（可指定类别：舰船数据/战斗机制/实例/黑话/人口…） |
| `get_ship_data` | 舰船精确查询（含模块、载机位、站位） |
| `get_ship_builds` | 查某船的官方加点树与方案 |
| `battle_simulate` | 调战斗模拟器算一场 |
| `web_search` | 联网搜索（搜索代理 → Tavily → 免 key Bing，多级降级） |
| `ask_user` | 需求不清时向用户提问澄清 |
| `make_fleet` | **配队输出专用**：AI 把方案作为结构化数据输出 → 前端渲染成方框卡片（不出文字表格） |
| `search_fleets` | 检索**配队库**（现成配队），AI 配队优先拿它当骨架 |
| `get_user_ships` | 查用户舰船库（仅在用户开启"允许 AI 检索"时可用） |
| `create_tool` | AI 自己写代码创建新工具，经"语法编译 + LLM 逻辑审查"自检后激活 |
| `create_skill` | 把可复用经验沉淀成 Skill |

### 4.3 三种运行模式

| 模式 | 说明 |
|---|---|
| ⚡ **快速** | 代码检索 + **只调 1 次 LLM**，零工具循环；实测 DeepSeek 下约 0.8~16 秒，429 风险最低 |
| 📋 **计划** | 先出执行计划书，你批准后才执行 |
| 🧠 **普通** | 完整多 Agent 流水线（默认） |

> 模式在**设置页**和**聊天页顶部**都能切。

### 4.4 会自己长大的部分

- **经验 Skill 沉淀**：每轮对话结束，AI 判断有没有可复用经验（配队思路/回答技巧/稳定偏好），有就沉淀成 Skill
- **自主创建工具**：现有工具不够用时，AI 自己写一个（必须通过语法编译 + 逻辑审查）
- **点赞/点踩反思**：对回答点赞或点踩（可填理由），AI 反思整段对话，更新 Skill 与用户画像

## 五、战舰配队页（`fleet.html`）—— 同时是"数据校验器"

这是整个项目的**数据权威**。任何来源（AI 给的、你手填的、导入的）人口/服役/载机位，最终都以它重算的为准。

### 5.1 能做

- **主舰队 + 增援**（增援不占人口、上限 9 艘）
- **超主力模块**：每个槽位（M/A/B/C/D/E）选变体；**同一艘舰可以有多套模块组合**（`⧉` 再加一套），服役上限按**舰船**在"主力+增援"合计
- **载机位**：按【模块来源 × 机型】分开——太阳鲸选 M2 出 8 个战机位、选 C1 出 5 个；大矛选 B2 才出护航艇位。每个位独立容量/独立按钮/独立机型限制
- **站位**：前/中/后排，船行上直接点着切换
- **旗舰**：按"条目"定位（同型舰多套配置不会串）
- **缝合**：勾上即忽略服役上限
- 实时统计：人口 / 舰载机 已用/可载 / 总结构 / 对舰·防空·攻城 / 模块数

### 5.2 会"报错"的地方（校验器）

`js/fleet_check.js` 是**唯一实现**，配队页、AI 工具、导入三个入口共用同一份逻辑：

1. 舰船必须存在于舰船库
2. **载机不得塞进没有载机位的船/模块**（无载机位、所选模块不提供该机型位、仅中小型位塞大型机、单个位超容量 → 报错并剔除）
3. 服役上限按**整队**（主力+增援）合计
4. 增援 ≤ 9 艘
5. 载机服役上限也按整队
6. **开启"允许 AI 检索舰船库"时**：用到的舰船与模块必须是**你拥有的**
7. 统计一律由舰船库重算，**AI 正文里的数字不作数**

### 5.3 三向联动

| 方向 | 怎么用 |
|---|---|
| AI → 配队页 | AI 调 `make_fleet` → 对话里出**方框卡片** → 点卡片进 `fleet.html` |
| 配队页 → 模拟器 | 「⚔️ 复制到模拟器」→ 选**目标舰队**（我方/敌方 × 护航/被护航）+ **追加/覆盖** |
| 配队页 → AI | 「🤖 发给 AI 分析/改进」→ 跳对话页自动填入并发送 |

### 5.4 配队库

把现成配队存成结构化条目（含每舰站位/数量/模块/载机），AI 配队时**先查它**，命中就当骨架微调，不再从零编。支持导出/导入 JSON，也支持 `data/fleet_library.json` 作为"内置只读"条目。

## 六、舰船加点（`addpoint.html`）—— 蓝点强化

### 6.1 数据来源（不用登录、不用截图）

官网**公开 CDN 静态资源**：`res/blueprint/ship_info/<编号>.js`（数值版）+ `zh-CN/<编号>.js`（中文文案）。
已全量入库：**177 艘 / 947 个系统 / 7106 个加点节点**，含坐标 `position[行,列]`、前置 `parentId`、逐级消耗与数值、中文说明。

### 6.2 页面

左侧系统列表（带进度条与"已用/上限"），右侧加点网格（按官方坐标排布、按前置连线）。
`点节点加点 / − 退级 / 重置`；**前置规则是「任一前置点开即解锁」**（不是全都要）。
**只显示所选模块对应的系统**（只选 M1+C2 就只显示那套；装甲/动力/指挥等舰船级系统永远显示）。

### 6.3 开战自动生效（核心）

```
加点页 → localStorage → 开战时 createShipInstance 自动套用
```
- 船级加成在算 `maxHp` **之前**应用；逐武器加成在 `weaponStates` 建好后**按系统**投到对应模块的武器
- 实测：大帝只点装甲/动力 → 结构 +28%、maxHp 141550 → **181184**（正好 ×1.28）；只点武器系统 → 首武器 单发+20 / 冷却−30 / 命中+25
- **取值规则**：取 `perLevel[当前等级]`，**不是各级累加**（冷却 5 级就是 15%）

### 6.4 属性分组

| 组 | 内容 |
|---|---|
| **A 组（10 项）** | 结构值 · 物理抵抗 · 能量抗性 · 伤害加成 · 暴击 · 锁定减免 · 冷却减免 · 单发伤害 · 闪避 · 拦截率（自动汇总 + 手动追加） |
| **B 组（4 项）** | 攻城伤害 · 维修量加成 · 命中加成 · 机库加成（引擎原本没字段，全靠手填） |
| **H 组（2 项）** | 机库暴击率 / 机库暴击伤害（只作用于本舰载机） |
| **M 组** | 打击间隔/被拦截率/受系统伤害/站位调整/武器分散打击/锁定效率/密集射击/系统内导弹拦截…（**只作用于本系统**） |

### 6.5 实现率

全库 **5186 个节点，已实现 4466（86%）**；非战斗未实现 477（速度 426/生产仓储 41/战略打击范围 10，按机制文档**速度不参与战斗**，本不该在舰队战引擎里做）；战斗相关未实现 243（167 种说明模板，其中 11 个是游戏术语代号待译文）。
**177 艘里只有 5 艘是完全实现的**（都是节点最少的）。

## 七、战斗模拟器（`simulator.html`）

### 7.1 编队

四支舰队（我方/敌方 × 护航/被护航）+ 轰炸编队。每支：主舰队 + 增援（≤9）+ 旗舰 + 缝合模式。
支持：选船弹窗（3 列/舰种筛选/多选/确认）、模块切换、载机按载机位分配、逐武器强化、站位切换、同型舰多套配置。

### 7.2 战斗引擎 —— 已实现的机制

| 机制 | 实现要点 |
|---|---|
| **时间** | `dt = 0.1 × 速度倍率`，逻辑步长固定 0.1 秒 |
| **目标选择** | 优先打击超主力（可勾）→ **直射必须先清最前排** → 按武器攻击序列匹配类型 → 随机；候选收缩 `max(1, round(候选数/2.5))` 防集火 |
| **开火循环** | 首射不需冷却；**锁定与冷却并行**；**同目标不重复锁定**；`弹药×攻击次数` 在 `攻击时长` 内均匀分批；**目标中途死则带剩余发数重锁**（不重置冷却） |
| **命中** | `(hitMin + rand×(hitMax−hitMin))/100 × (1+(锁定效率−闪避)/100)`，clamp 0.01~0.99 |
| **拦截** | 按模块合成到舰船；`Π(1−r/100)` 累乘（全局/同排/自身）；**直射武器不会被拦截** |
| **伤害** | 调校系数 **1.3**；物理=**减法**、能量=**乘法**；**不破防只吃 10%**；能量抗性 ≥100% → 0 |
| **暴击** | `(武器 crit?15%:0 + 强化) × (1.5 + 强化暴击伤害)`，作用于最终单发 |
| **加成** | 大盾旗舰全场 ×0.7；**被护航舰在护航存活时伤害=0** |
| **系统破坏** | 定向（`subSystemTargets`，效率 高60%/中40%/低20%）+ 10% 随机；被毁模块**全部武器停火**；25 秒修一次，维修次数 指挥3/自修2/其它0；**只有动力系统**被破坏扣 5% 最大结构 |
| **母舰与载机** | 载机部署按**条目**分摊（部署总数=你在配队页填的数量）；**母舰被毁 → 其载机一起被毁** |
| **维修** | `面板维修/60 × (1 + min(物甲×0.25,150)%)`，选血%最低的友军 |
| **轰炸模式** | 距离每偏离 15 吉米 ±2% 命中 |

### 7.3 战斗引擎 —— **未实现**的（如实标注）

| 缺口 | 原因 |
|---|---|
| **拦截率/闪避率** 大部分船没有 | 全库只有 **5 艘**有拦截率（雷火之星B2 27%、光锥级区域防空 23%、大盾B3 12.8%、太阳鲸C3 5%、CV3000 A2 12%），**0 艘有闪避** → 这两个机制对多数船是空转 |
| 防空三态（反击/区域/主动）、舰载 15%/机载 60% 命中 | 数据有 `antiAirType` 但代码不读 |
| 系统**独立血量**（"绝育"玩法） | 现在是"概率直接摧毁"，没有系统血量概念 |
| 策略系数 / 打系统武器打结构 ×0.8 | 数据基本没有 |
| 战机两种模式（独立作战/往复打击）+ 飞行时间 | 数据有 `flightMode` 但不读 |
| 母舰机库加成 | 无数据 |
| 旗舰技能 | **只实现了大盾一种** |
| 速度/距离参与交战 | 代码不读 `speed`，无先后手、无接敌距离 |

### 7.4 模拟精度现状（重要）

- **模拟器自身随机波动约 ±9%**（12v12 镜像实测：时长 908~1083 秒）
- **单场战斗结果不能作为精度判据** —— 分不清是模型偏差还是运气；要**同一场多打几次取均值**
- 12v12 镜像战（4大盾+4大矛+4大帝，每方 210 万结构）现在 **756~967 秒结束**，镜像 6 次各胜 3（**无单边偏袒**）
- 逐武器核对：**实测输出与《舰船资料》面板 DPM 误差仅 1~3%**（超主力模块武器 100% 准）

`TF-IDF 稀疏检索`（中文 bigram） + `bge 稠密检索` → **RRF 倒数排名融合** → 元数据分层加权（音频口语稿降权、结构化舰船/配队升权）→ 相邻块上下文扩展 → 噪声过滤 → 质量门控 CRAG（低分触发改写二次检索）。

## 十一、踩过的坑（避免重犯）

1. **shell 里写正则会被吃转义**（`\d` → `d`）→ 这类替换一律用 Edit / 写文件，不用 `node -e` 拼字符串（已犯多次）
2. **heredoc 会吃掉反斜杠**（Windows 路径必挂）→ 测试脚本一律用 Write 生成
3. **`JSON.stringify(db, null, 2)` 会把紧凑单行库写成 2 万行** → 必须 `JSON.stringify(db)`
4. **`｜`(U+FF5C) 与 `│`(U+2502) 是两个字符** → 分隔符解析必须都放进字符类
5. **引入行 uid 后，所有"拿参数查舰船数据"的地方都要改**（否则弹窗空白）
6. **载机条目必须是完整舰船对象**（只写轻引用会导致载机零输出）
7. **onnxruntime 批量嵌入会 OOM** → 重建向量索引用单条嵌入；或只对变更块增量重嵌
8. **`timeout` + 管道会让被杀进程的退出码变成 0** → 长任务别加 timeout，或写成日志再查
9. **对比面板 DPM 要按武器主目标选字段**（攻城在 `dpm.siege`）→ 拿 `antiShip` 比会得出假的巨大偏差
10. **headless 视口太矮时配队页底部 fixed 统计栏会盖住船行** → 测试需 `setViewport({height:1400})`
