## 总览：这个项目是怎么长出来的

一句话概括这条路径：

```
AI 对话问答（8/11–8/26）
   ↓  发现"光会答不够，得能配队"
战舰配队 + 三向联动（9/15–9/16）
   ↓  发现"配出来的队不知道强不强"
战斗模拟器 + 数据校验（9/17–9/18）
   ↓  发现"模拟器要准，数据必须先准"
数据核实 + 模块武器补齐（9/18–9/20）
   ↓  顺带做了：舰船加点（蓝点强化）全链路（9/19）
```

**贯穿全程的一条主线**：不断把"AI 自由发挥"替换成"代码算准 + AI 只负责表达"。到 9/20，配队页已经变成整个项目的**数据权威**——任何人（包括 AI）给的人口/服役/载机位，都要按它重算。

## 阶段 6｜配队逻辑大修 + 战斗引擎（9/17–9/18）：**发现问题的密集期**

### 6.1 战舰配队"大量逻辑 BUG"（9/17）
用户一句"目前战舰配队有大量的逻辑 BAG"引出 **7 个真 bug**，最有价值的是**载机位模型重做**：

- **根因**：载机位原来按**机型**合并成一个池子（太阳鲸 M2(8战机)+C1(5战机) → 合并成 13 个位、一个按钮），而且只要有一个 `ALL` 槽，整池的机型限制就被放开
- **重做**：载机位 = **【模块来源】×【机型】**，每个组合独立容量/独立机型限制/独立按钮；载机条目加 `slot` 字段
- 同批修的还有：载机可超容量、服役上限不跨段（只看当前段）、站位全链路丢失、**旗舰 ⭐ 从未显示**（`isFlagship` 永远没赋值）、不屈级误显模块按钮、「我的配队」舰载机用机库数、**`renderLib()` 从未被调用**、`FleetLib.all()` 的 `_from` 放错位置

**这轮确立了一套方法论**：用 **puppeteer 驱动本机 Edge + python http.server** 跑真实浏览器回归，直接 `evaluate` 调页面内函数复现。

### 6.2 模拟器选船重做 + 单一数据源（9/18）
- **发现模拟器内联了一份 250KB 的舰船数据副本，与 JSON 有 202 处差异**（战机被算 10 人口、服役数错、完全没有模块载机位、还留着已删的 FSV380）→ 改为 fetch 单一数据源
- 选船重做为配队页那种 3 列弹窗
- 新增 **`js/fleet_check.js` 校验器** ——「战舰配队就是检查器」：载机不得强塞、服役整队、启用舰船库时校验所有权、统计一律重算
- 「复制到模拟器」可选目标舰队（4 个）+ 追加/覆盖

### 6.3 载机数量"8 个变 40 个/×56"（9/18）
用户报"录入 8 个，到模拟器变 40 个"。查了两层：

| 层 | 根因 | 修法 |
|---|---|---|
| ① | 「复制到模拟器」**默认"追加"**，连点 5 次 8→16→24→32→**40** | 默认改「覆盖」+ 追加标注累加风险 |
| ② | **载机按"每艘母舰各发一份"部署** —— 配队页填的 8 是**整条目合计**，而战斗给 6 艘各发 8 架 = 48 | `deployAircraft` 改为按条目**平均分摊**，部署总数=填写数量 |

**定位方式值得记**：这次是**直接看用户的真实浏览器**——`ctypes EnumWindows` 抓窗口标题 → `PIL ImageGrab(bbox=GetWindowRect)` 截图 → 在截图上看到 `海尔波普-维修支援护航艇 ×56`，再对照配队页的 18/18，一眼看出是"乘了母舰数量"。

同批还揪出一个**会丢数据的存储冲突**：模拟器与配队页**共用 localStorage key `lagrange_fleets`** 但结构完全不同 → 任何一边保存都会清掉另一边。已拆分到 `lagrange_sim_fleets` + 安全迁移。

### 6.4 按《战斗机制》文档校正引擎（9/18）
用户提供权威机制文档，逐条对照后修正 **4 处**：

| # | 修正 | 实测 |
|---|---|---|
| 1 | **开火循环：锁定与冷却并行 + 同目标不重复锁定**（原是串行，周期=冷却+锁定） | 冷却10+锁定6 → 周期 **10.1s**（原 16s） |
| 2 | **直射武器不会被拦截** | 100% 全域拦截下：直射拦 0/300、投射 300/300 |
| 3 | **只有动力系统被破坏扣 5% 血**（原任何系统都扣） | — |
| 4 | **母舰被毁 → 载机跟毁**（`carrierInstId`） | 2 艘母舰各 4 架 → 毁 1 艘后剩 4 |

### 6.5 模块武器补齐（9/18）——**修复"打上万秒"的根因**
用户报"游戏里 3-4 分钟碾压结束的配队，模拟器里打上万秒还巨大劣势"。

**根因**：超主力的武器存在**模块变体**里，而 **233 个变体全部没有 `weapons` 字段** → **17 艘超主力在战斗里一门炮都没有**（实测 20000 秒、双方 0 伤害）。

**数据来源**：知识库那 **187 份《舰船资料》**（每艘一份，含每个模块变体的 武器名/数量/每分钟伤害/伤害类型/优先目标/单发伤害/特性）。

**提取方法（关键）**：按机制文档的「面板分钟伤害」公式**反推冷却**：
```
冷却 = 单发伤害 × 数量 × 60 ÷ 每分钟伤害
```
→ 填充 **92 个变体 / 126 门武器**，**实测每条武器输出与资料面板 DPM 误差仅 1~3%**。
效果：有武器的舰船 **90 → 183 艘**；12v12 镜像战 **20000s/0伤害 → 756~967s 结束**，且无单边偏袒。

同批按用户指示以资料真值修正 **9 艘占位结构值**（原 50000 → 真值，含 6 架战机）。

- **开战自动生效**：`createShipInstance` 自动套用（船级加成在算 `maxHp` **之前**应用；逐武器按系统投递）——实测大帝只点装甲/动力 → 结构 +28%、maxHp 141550→**181184**
- **取值规则**：取 `perLevel[当前等级]`，**不是各级累加**

### 7.3 批量实现机制 + 修正误判
- 实现：两列型暴击 / 掩护（拆 base·时长·目标数，受击伤害转由掩护舰承担）/ 周期爆发 / 锁定效率（**原被错归成"锁定减免"**，实际是加命中）/ 密集射击 / 系统内导弹拦截 / 武器分散打击 / 苍穹 M1 协同打击 / 安东塔斯三种打击 + 协同指挥 A/B/C
- **实现率 4466/5186 = 86%**

### 7.4 用户核对时抓到的两个超主力 bug（9/19）
- **(a) 系统名对不上**：`subSystems` 用**槽位名**（"A武器系统"），而武器用**变体名**（"'利剑'指挥系统"）→ 名字匹配失败 → **所有超主力"系统被毁后武器照打"**。修后实测：全部系统标记被毁 → 60 秒伤害 = 0
- **(b) 维修次数用错判据**：用模块 `selfRepair` 标记 → 超主力全 0 次、一毁永久。改按《战斗机制》文档**按系统类型**（主武器 2 / 机库 2 / 指挥 3 / **动力 0**）

### 7.5 系统破坏数据按资料重建
- 上一轮曾判"9 条 subSystemTargets 找不到出处"，**这是搜错词了**——资料里成体系写着「系统打击（概率损毁目标舰船系统，打击序列：X系统效率低/中/高）」
- 按资料写入 **14 门**（9 条带 `_sysBreakSrc`、5 条无出处已标 `_sysBreakUnsourced` 未删）

## 阶段 8｜数据核实 + 文档 + 额度治理（9/20）：把地基夯实

### 8.1 猎兵级 hp 定案（六源交叉）
资料 md 写 **1120**、同型船体与其余五处来源全是 **76190**。决定性证据：原始 txt 原文写「血量（结构值）：**显示数值**1120」——是**从游戏界面截图读数误抄**。**定案 76190**。

### 8.2 修正 12 处资料错误
187 份《舰船资料》里有 12 份「舰船类型」写错（安东塔斯/雷火之星被写成"驱逐舰"）。根因查明：**2026-08-24「桌面拆分 1050+md」批量生成时串行**（原始 txt 分类是对的）。

修的时候又踩坑：**整库重建向量索引会 OOM**（onnxruntime 批量嵌入）→ 改用**增量脚本只重嵌变更块**（12 块 1 分钟 vs 整库 17 分钟且会挂）。

### 8.3 三份文档
- **《项目全介绍》**（15 节，概览）
- **《全量功能清单》**（18 节，逐条清点 11 页面/16 模块/11 工具/16 处提示词/数据层/24 存储键…）
- **《【交接】继续完善…》**（给接手的人，含数据格式约定与 P0~P5 下一步）

### 8.4 Agent 额度治理（本次）
用户要求：**加回限制（总 200 / 单 35 / 循环我来定）**，但——

> 「限制到了**不要直接强行停止**，而是想办法让他根据现在的给出输出，或者再给他一点点额度找重要的，反正就是**不能直接截停**要他给出输出」

于是设计成**三级降级**（不是拒绝式截停）：

| 级别 | 触发 | 行为 |
|---|---|---|
| 常规 | — | 总 200 / 单工具 35 / 主循环 **80** 轮 |
| 软提醒 | 用掉 80% | 注入【系统提醒】告知剩余次数，要求开始收敛 |
| 关键追加 | 常规用尽 | 只允许关键工具（检索/舰船/模拟/配队），总 +40、单工具 +12；非关键工具停用并说明原因 |
| 强制收尾 | 追加也用尽 / 轮数到顶 / 被拒 6 次 | **停用工具、注入收尾指令**，要求"已有数据照常给出、未取得的部分如实标注、不编造" |

**保证一定有输出的三道保险**：
1. 收尾阶段 LLM 调用**不传 tools** → 模型只能产出正文
2. 模型仍硬要调工具 → 推回指令最多 3 轮，之后兜底文案发 answer
3. 拒绝工具时不是报错，而是把"**还剩多少额度、下一步该干什么**"写进工具返回，让模型自己收敛

**验证方式**：拦截 `fetch` 造一个"疯狂刷工具"的假模型 → 实测 ✅80% 提醒 ✅关键工具模式 ✅停用工具收尾 ✅被拒 6 次后收尾 **✅最终仍产出 answer（未硬截停）**，全程 2.1 秒。

## 值得单独记的几条"规律"

### 1. 反复出现同一类问题："看起来功能没生效，其实是数据/名字对不上"
- 超主力零输出 = 模块变体没 `weapons` 字段
- 系统被毁不停火 = 槽位名 vs 变体名不匹配
- 载机位不显示 = 数据里没有 `aircraftSlots`
- 「强化」空白 = 传进去的是行 uid，却拿去查 `SHIP_DATABASE[shipId]`
- 整船打不死 = 强化字段缺失导致伤害变 `NaN`

**结论**：这个项目里，"AI 不听话"的比例远低于"数据/标识符对不上"。

### 2. 限制值的完整摇摆史
```
8/20 → 8/300 → 30/300 → 1e12(全放开) → 25/80 → 20/50/40(定稿)
→ 9/13 全部改无上限 → 9/20 加回 200/35/80 + 引导收尾
```
**这次的差别**：以前是"到顶就拒"，这次是"到顶引导收敛并保底出答案"。

### 3. 测试方法论的三次升级
| 阶段 | 手段 | 局限 |
|---|---|---|
| 早期 | 读代码推断 | 漏得多（前端状态机太绕） |
| 9/17 起 | **puppeteer 驱动本机 Edge** + 直接调页面内函数 | 只能测自己的环境 |
| 9/18 起 | **看用户的真实浏览器**（EnumWindows + ImageGrab + pyautogui） | 慢，但"用户说还在"时最有效 |

### 4. 数据源不断被"去重、对齐、定权威"
一开始到处是副本：模拟器内联副本、后端 `lagrange_docs`、小程序 `utils`、质料老构建…最终确立 `data/ship_database.json` 为**唯一数据源**，并由**配队页当校验器**兜底。到 9/20 只剩两处旧副本（193 艘）待清。
