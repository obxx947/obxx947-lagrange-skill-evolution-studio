# 第一部分 · 这是一个什么项目

## 1.1 一句话
《无尽的拉格朗日》（现名《星际猎人》）的 **AI 战术顾问 Web 应用**，纯静态前端（无后端依赖可跑），
核心是一个**自研战斗模拟器**：能吃两份真实游戏战报做 **18 项指标验收**，能脱离浏览器在 Node 里跑（用于进化实验）。

## 1.2 目录与三份副本（**重要**）
| 路径 | 是什么 | 要不要改 |
|---|---|---|
| `拉格朗日智能体3/` | **工作副本（唯一要改的）** | ✅ 改这里 |
| `lglr.html/` | 部署源（GitHub Pages 从这发布，仓库 `github.com/obxx947/lglr`，SSH） | 改完从工作副本同步过去再 push |
| `拉格朗日智能体/web/` | 后端仓库里的 web 副本（HTTPS） | 同上 |
| `知识库2/` | 知识库（A资料 737 份 + 舰船资料 + 例子 31 份 + 数据，约 22MB） | 只读素材 |

**同步动作**（每次改完必做，否则三份会飘）：
```bash

# 然后各自 git add/commit/push（只推 页面/data/回归测试，不推工作脚本）
```

# 第二部分 · 我们现在在干什么

## 2.1 主线：把模拟器精度压到 15% 以内
用户定的验收协议：**两份真实战报各跑 3 次取均值，18 项指标（时长/对舰/对空/维修/生存占比…）偏差必须 <15%**。
**当前 13/18**（本轮从 11 提到 13）。

**已达标 13 项**，剩下 5 项与卡点（都有实测证据）：
| 未达标项 | 现状 | 卡在哪（已定量） |
|---|---|---|
| 战报2 时长 | +41% | 我方总结构 997万 ÷ 敌方对我 1.86万/s；关键舰结构偏高（CV3000 我 39.2万 vs wiki 27.8万） |
| 敌方护航→我被护航 对舰 | −55% | **部分是我方修复的正当结果**（护航隔离后打不到我被护航队），游戏那 56万 很可能来自"我方护航被打死后那段窗口" |
| 敌方护航 生存占比 | 41% vs 86% | **悬崖效应**：它总血 413万，游戏打 395.9万（<血→不死），我打 466万（>血→全灭）。13% 的伤害差决定生死 |
| 敌方被护航→我被护航 对空 | −22% | 与上一条**敏感方向相反**（改一处另一处爆），真实差距在**损失分布** |
| 敌方护航→我被护航 对空 | −98.7% | 载机免疫 bug（见下）+ counter 触发窗口稀薄 |

## 2.2 ★ 最重要的结论：现在这版"准"是一张【补偿网】（**先读这条，能省你几天**）
| 我改什么 | 更符合官方？ | 验收变化 |
|---|---|---|
| 护甲改成官方真值（55 艘） | ✅ | 11 → **7/9/8（越准越差）** |
| 系统结构值改成官方逐舰表 | ✅ | （旧记录）时长从 579s 打到 327s |
| 载机往返时间归零（官方说冷却已含往返） | ✅ | 12 → **8** |
| 分摊取整 floor（三源一致） | ✅ | 12 保持 |
| 护航隔离恢复（KB+用户口述） | ✅ | 11 → **12** ✓ |
| 修 7 艘战机「占位 4000」结构值 | ✅ | 12 → **13** ✓ |
**含义**：现在的精度靠"几处偏错的数据 + 两个偏错的机制参数"互相抵消（护甲偏低↔缺"物理护甲%"档；载机多算往返↔杀得太快；SHOTS_CALIB=1.25/基础暴击 15%↔面板换算缺口）。
**所以：单项改准必然变差，必须成组重标定。** 别再单项试一遍我们踩过的坑。

## 2.3 已经确认但**还没修**的真 bug（下一位接手请优先）
1. **被护航队的载机也被护航免疫**：`simulator.html` 的 `if(escortAlive) dmg = 0;` 把载机也算进去了，而 KB 明确「载机不受此保护」。
   实测：**137~140 万伤害被清零（占全部伤害尝试的 9%）**；铁证：谷神星 CAT-3 打我的 BR050-轰炸机 **1430 次命中、总伤害 0**。
   ⚠️ **单改会崩**（时长 544→679s、某指标崩到 4.8 万）→ **必须与"什么时候可以打被护航队"一起改**。
2. **`vsShipMul`（逐武器对舰倍率）** 只有 94/439 门武器有值（已补 23 门，剩的是单一用途武器，本就该为 1）。
3. **`重点支援` 机制的"支援"含义未核实**（4 个节点副本，是待做机制里最多的）→ **不许猜**。
4. `{ED9294}`（缜密射击）/ `{ED9299}`（拦截突防）两个术语未解码 → 要先补 `_build_bpstats.js` 的 `DECODED` 表。
5. **40 种机制引擎没吃到**，清单与逐条实现方案（A/B/C 分级 + 可照抄补丁）在 `_report_mechanics.md`。
   本轮已落地其中 4 条（自适应控制 / 备用弹药 / 信息伪装接线 / 重点目标）+ 另外 3 条（多目标同步打击 / 弱点定位 / 防空强化）。

# 第三部分 · 这台新设备能不能胜任（本机实测对照）

## 3.1 旧设备（我做这轮实验用的）实测
| 项 | 实测 |
|---|---|
| CPU | Intel i5-2450M **4 线程** |
| 内存 | **1.91GB 总**（可用常年在 0.1~0.25GB 之间晃） |
| 磁盘 | C 盘剩 **1.5GB**（96% 已用） |
| 引擎加载 | 86ms / 常驻 **85MB** |
| **随机小队混战**（4~12 艘/边） | **≈12 场/秒（单线程）** |
| 战报级大舰队（10+ 舰/边、含载机） | **≈1.2 场/秒（单线程）** |
| 一次"护航对弈"（参数级）一代（6 个体 × 3 对手 = 18 场） | ≈15 秒 |
| 方案二B 最小实验 **100 代**（6 个体 × 3 对手 = 1800 场） | **784 秒**（越到后期战斗越长） |

## 3.2 你计划的每个模块，本机能不能跑
| 模块 | 计算特征 | 旧设备（4线程/1.9GB） | 新设备（16核/46GB） |
|---|---|---|---|
| **方案二B 最小版**（存活时间 + 随机变异） | 每代 pop×opp 场战斗 | ✅ **能跑**（实测 50 代 150s） | ✅ 随便跑 |
| **方案二A NEAT**（加节点/加连接 + 规模惩罚） | 每代还要跑一次网络前向（微秒级） | ✅ 能跑（瓶颈是战斗，不是网络） | ✅ |
| **E8 行为投影**（240 根向量 × 8 维） | 每场战斗后一次点积 | ✅ 可忽略 | ✅ |
| **MAP-Elites 分箱 + Archive** | 每代查/写格子 | ✅（几千格 JSON 很小） | ✅ |
| **自对弈（交替进化）** | 战斗数 ×2 | ✅ 但耗时翻倍 | ✅ |
| **1000 代持续进化** | 1000 × pop × opp 场 | ⚠️ 大舰队 1.2 场/秒 → 1000 代 × 18 场 ≈ **4 小时**；内存/磁盘吃紧 | ✅ 16 线程 ≈ **69,000 场/小时**，一代 <1 秒 |
| **LLM 观察层** | 网络往返 | ⚠️ 与设备无关，**受 API 配额限制** | 同左 |
| **浏览器里的前端进化**（若想搬进网页） | Chrome 要 300~700MB | ❌ **可用内存不够**（只剩 0.1~0.25GB） | ✅ 46GB 完全够 |
| 磁盘快照（每 100 代导出 Archive） | JSON | ⚠️ 只剩 1.5GB，要省着写 | ✅ |

## 3.3 结论
- **方案二B（混沌生长）在旧设备上就能跑**，我已经跑通了最小版并拿到上升曲线 ✓ —— 换设备主要是为了"跑得更久、跑更多代、能同时跑多套"。
- **方案二A 的 NEAT/E8/MAP-Elites 计算量也不大**（每代多的是战斗而不是网络），**旧设备能跑小规模，新设备能跑大规模**。
- **真正的瓶颈有两个，换设备只能解决其中一个**：
  1. ~~内存/磁盘~~ → 新设备解决 ✓
  2. **LLM 观察层与"变异提示词"要走 API**（配额+费用）→ 换设备**不解决**；建议把"变异算子"做成**纯引擎侧（随机/遗传算子，不调 LLM）**，LLM 只用于"每 N 代翻译一次"。
- **新设备（16核/46GB）推荐跑法**：`worker_threads` 开 16 个并行 worker，每个 worker 一个"进化岛"，主进程做 MAP-Elites Archive 合并；LLM 观察层每 100 代调一次。

# 第四部分 · 硬规矩（踩过的坑，请勿重踩）

1. **不许硬编码两份战报的配队结果**；改动必须实测，验收下降就回滚（除非是"数据纠错"，那种要留证据链）。
2. **改大文件不用 Python 的 `'w'` 模式** —— `io.open(p,'w')` 会先截断再编码，遇编码错会把文件清成 0 字节（我们已把 583KB 的 `simulator.html` 清空过一次；恢复办法：`engine/lagrange_engine.js` = 垫片 + `fleet_check.js` + 内联脚本 + 导出块，切回来即可）。
3. **改 `data/ship_database.json` 必须用 `JSON.stringify()` 单行写回**；改 `data/blueprint_stats.json` 必须通过 `_build_bpstats.js`，**改完与旧库逐节点 diff，丢条件数必须为 0**（历史上重建静默丢过 15 个条件触发节点，症状是"验收变好"）。
4. **HTML 字符串拼接的行级容器必须闭合**（战报每行 `<div>` 漏闭合 → 行行嵌套 → 点哪条船都显示第一条）。
5. **弹窗打开必须 `classList.add('active')`**（只写 `style.display='flex'` → 全屏透明但仍拦截点击 → "点不动"）。
6. **页面控件必须真 dispatch 事件**（`page.mouse.click`），直接调 JS 函数会绕过内联事件 bug。
7. `let/const` 声明的变量**不挂 window**；探针要读裸变量名。
8. **改了 `simulator.html` 要 `node _build_engine.js`**，否则 Node 测试用的还是旧引擎。
9. **子智能体在 ZCode 里要先用 UI 选思考档位**，否则报 `reasoning-level-missing`；且**应用更新会杀死在跑的子任务**。
